# HYP-001 — redgreen's stop sits inside the noise, so a real entry edge never gets to express

**Status:** proposed
**Date:** 2026-08-28  **Pod:** redgreen

## Claim

redgreen's entry signal beats a random entry on the same symbols in the same
session window by **6.6x at 5 minutes** (+67.8 bps vs +10.2 bps, n=13,870).
Its default stop is 1–4% — inside the 5-minute noise of these names — so
**77% of its trades exit on the stop** before that drift can appear. Widening
the stop to `stopAtrMult 12 / minStopPct 30 / maxStopPct 90` drops stop-outs
to 11% and takes profit factor from **0.81 to 1.33**.

Position size falls automatically when the stop widens (`qty = equity *
riskPct / risk`), so this is a test of **stop distance alone, not leverage**.

## Category

(c) parameter range in `lib/strategy.js` — and this is the load-bearing part:

```
current RANGES     stopAtrMult [0.8, 3]   minStopPct [1, 4]   maxStopPct [4, 12]
region tested      stopAtrMult 6-12       minStopPct 8-30     maxStopPct 30-90
```

**The winning region is entirely outside the tuner's search space.** No amount
of tuning could ever have found this, which is itself the finding: the search
bounds were an untested assumption, not a measured constraint.

## Mechanism

The signal selects names with genuine short-horizon upward drift, but a 1–4%
stop on a $1–5 stock is roughly one bar of ordinary range, so noise removes the
position before drift accumulates. Widening the stop converts a high-frequency,
stop-dominated pod into a low-frequency one that holds long enough for the
measured drift to arrive, at proportionally smaller size.

## Falsifier

**Written before the tuner has seen any of this.** This dies if any of these hold:

1. The improvement does not survive the frozen 60/20/20 holdout in `lib/tune.js`
   — i.e. holdout profit factor at the wide-stop setting is not > 1.0.
2. The gradient is cost artefact rather than edge: if re-running with
   `slipBps 0` shows the same monotonic climb, the gain is mostly fewer round
   trips, not the drift thesis.
3. It does not survive a third split. The observed halves are H1 0.83 -> 1.39
   and H2 0.77 -> 1.31, but **I selected these parameters while looking at both
   halves**, so those are in-sample to my search. A chronological third cut, or
   the frozen holdout, is the only honest read.
4. Removing the stop entirely (`maxStopPct 999`) scores as well or better —
   that would mean this is not "a wider stop" but "no stop", which is a
   different and much more dangerous strategy that the live engine's
   off-hours stop handling is not built for.

## Cost

No change to `lib/data.js` discovery — same movers, same universe. Trade count
falls 3,152 -> 2,050 (-35%), so this reduces exposure and commission surface
rather than adding to it.

## Note to the red team

Do not grade this gently because it is the only positive result in the repo.
Two specific things I could not rule out myself:

- The same widening lifts **every** pod's profit factor (gapgo 0.70 -> 0.84,
  reclaim 0.62 -> 0.87) including pods whose entry is *worse than random*.
  That strongly suggests a component of the gain is simply **fewer round trips
  paying less slippage**, not the drift thesis. Only redgreen crosses 1.0, and
  the drift thesis has to explain why — falsifier #2 is the test.
- At 11% stop-outs this pod barely has a stop. Check what actually closes the
  remaining trades and whether the live engine's premarket/after-hours
  engine-managed stop path behaves sanely at a 90% stop distance.
