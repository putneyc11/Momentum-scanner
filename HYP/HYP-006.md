# HYP-006 — the tuner's frozen bar is a floor, not a standard, so it screens nothing

**Status:** proposed
**Date:** 2026-08-28  **Pod:** (all — this is `lib/tune.js`, not a pod)

## Claim

`lib/tune.js:98` sets the acceptance bar from the incumbent's own score:

```js
const validBar = valid.length ? evalOn(valid, champ) : champTrain;
```

The freeze fixed a real leak — the bar no longer walks upward as the search
finds it. But it is still **relative to whatever the incumbent scores**, and
our incumbents are catastrophic. Measured across Builder's six HYP-002 arms:

```
redgreen  base validate −44.48   base holdout −53.88
reclaim   base validate −93.73   base holdout −93.33

acceptance in all six arms:  N/N   (22/22, 11/11, 20/20, 22/22, 17/17, 12/12)
```

**Every candidate that clears the train filter also clears the validate bar,
in every arm, for both pods.** The bar rejects nothing. We have been reading
acceptance counts as a measure of selectivity when they measure nothing at all,
and "held" against a base of −53.88 means only that a number exceeded a floor.

## Category

`lib/tune.js` search mechanics.

## Mechanism

Selecting for "better than the incumbent" is only meaningful when the incumbent
is decent. Against a pod losing 44 points on validate, the criterion degenerates
to "not catastrophic," which almost every draw satisfies, so the champion is
whichever candidate the walk happened to reach last rather than one that met a
standard.

## Falsifier

1. Re-running with an absolute floor added — a candidate must clear both the
   incumbent *and* some fixed threshold — leaves acceptance counts and
   champions materially unchanged. That would mean the relative bar was already
   doing the work.
2. The N/N pattern is an artefact of the train pre-filter (`tScore <= champTrain
   → continue`) doing all the screening, and the validate bar is redundant
   rather than inert. Distinguish by counting candidates rejected at each stage.

## Cost

None to discovery. Expect far fewer accepted candidates and possibly zero for
pods that cannot clear an absolute standard — which is information, not failure.
