# HYP-007 — the screen cannot be measured, because the data is the screen's own output

**Status:** proposed (blocked — this is a data-collection change, not an experiment)
**Date:** 2026-08-29  **Pod:** (none — `lib/data.js` discovery and day recording)

## Claim

Every symbol in every recorded day file **already passed the screen**. There is
no negative class anywhere in the library, so the screen's false-negative rate
is not merely unmeasured — it is structurally unmeasurable from this data, and
will remain so no matter how many days accumulate.

The chain, `lib/data.js`:

```
discover()  filters on MIN_PRICE / MAX_PRICE, then PM_PCT_FLOOR (10) or
            RTH_PCT_FLOOR (25) / FAST_PCT_FLOOR (12), then ranks by pct and
            slices to MAX_UNIVERSE * 2                          (:209)
noteMovers(today, ranked)   <- called on the ALREADY-FILTERED list  (:210)
```

and `engine.js:433` records `universe ∪ posMeta ∪ moversSeenToday` — three sets
that are all downstream of that filter. `lib/backfill.js` applies the same
thresholds, so backfilled days inherit the same property.

**A second gap makes even the surviving names hard to study.** `discover()`
computes `prevClose` for every candidate (`lib/data.js:205`) and then throws it
away: `recordDay(symbolsBars)` receives bars only, and a day file is
`{date, symbols:{SYM:[{t,o,h,l,c,v,m}]}}`. Percentage change is defined against
the previous close, so **the minute a symbol first crossed the screen cannot be
reconstructed** from a day file — not even for symbols that are in it.

## Why this matters now

Two independent lines of work are blocked on it:

- Red Team's ruling on HYP-001: *"To attribute value to screening, reconstruct
  and persist each symbol's first discovery timestamp, then compare predeclared
  post-discovery entry policies; the present day files and future-signal-
  conditioned pools cannot identify that layer."*
- The redirect after the entry-trigger result. If the trigger contributes
  nothing, the screen is the obvious next place to look — and it is the one
  layer in the system that has never been measured at all.

Every threshold in the screen is an untested assumption: `PM_PCT_FLOOR 10`,
`RTH_PCT_FLOOR 25`, `FAST_PCT_FLOOR 12`, `PM_MIN_VOL 25000`,
`MIN_DAY_VOL 5e6`, `FAST_VOL_FLOOR 3e5`, `MIN_PRICE 0.03`, `MAX_PRICE 100`,
`MAX_UNIVERSE 20`. Nobody knows what any of them buys or costs.

## What has to be recorded, and it is additive

1. **Rejected candidates.** A sample of names that reached `discover()` and
   failed, with the reason and the values that failed — price, pct, volume.
   Without a negative class there is no screen experiment, only a description
   of what got through.
2. **`prevClose` per symbol**, which already exists in `cands` and is discarded.
3. **First-qualification timestamp** per symbol — the minute it crossed, not
   the minute we happened to poll.
4. **The rank and the reason it qualified** (premarket / classic RTH / fast),
   so `MAX_UNIVERSE 20` can be evaluated as a cutoff rather than assumed.

Items 2 and 3 are **retroactively recoverable** for existing days — Alpaca has
the daily bars, and the crossing minute is computable once `prevClose` is known.
**Item 1 is not.** Rejected names were never fetched, so the negative class can
only start accumulating from the day this ships.

## Falsifier

1. A negative class already exists somewhere I have not looked — a log, the
   journal, or a field in the day files — in which case this is unnecessary.
2. `moversSeenToday` turns out to be populated before the pct/price filters
   rather than after, making the recorded set wider than the screen's output.
   Check `lib/data.js:209-210` — `ranked` is built from `cands`, which is
   already filtered, so I believe it is after; disprove it if not.
3. The crossing minute is not reconstructible even with `prevClose`, because
   intraday pct in `discover()` is computed against a daily bar that itself
   moves during the session.

## Cost

No change to what is traded. More disk per day, one extra fetch for a rejected
sample. **The clock cost is the real one: the negative class only exists from
the day it ships**, so every day this is deferred is a day the screen stays
unmeasurable.

## Sequencing

Independent of HYP-005 and HYP-006 — it touches no execution or search code,
and it is graded on forward returns, which carry no cost model. It can be built
in parallel with the exit cap. **It should be, because it is the only item
whose value decays with delay.**
