# HYP-003 — surge buys the last print of a 3-bar squeeze; the first expansion bar buys the same event at the start

**Status:** proposed
**Date:** 2026-08-28  **Pod:** surge

## Claim

Replacing surge's entry (`igniterSignal`: three consecutive green bars totaling ≥3% with volume ≥3.5× avg10) with the **first expansion bar** — a single green bar that (1) prints volume ≥ `volSurgeMult` × avg10, (2) closes above the prior 5-bar high, (3) opens within 2% of VWAP, (4) is not preceded by another green volume-surge bar, (5) has RSI14 < 80 — takes +5m forward return from **−18.7 bps (n=14,168) to +46.0 bps** against a **+13.7 bps** random baseline on the same names and session window (**3.37×**, n=34,127, 0.464% of 7,349,065 window bars). At +60m the same signal is +197.7 vs +114.5.

## Category

(b) entry signal in `lib/strategies.js` — **surge only**. New `signalAt`. Do **not** edit `igniterSignal`; igniter still uses it. Do **not** give the rider a target (invariant #4). `burstPct` becomes unused by this pod; leave `RANGES` alone.

Exact conditions at bar `i` (all causal, `avg10` already excludes the current bar):

```
inWindow, i >= 10, atr[i] present
close > open                                          // green
v >= volSurgeMult * avg10[i]                          // 3.5× default
close > vwap[i]
rsi[i] == null || rsi[i] < 80                         // pinned; do not use P.rsiMax (default 90)
NOT (prev bar green AND prev v >= volSurgeMult * avg10[i-1])   // first bar of the expansion
close > max(high of bars[i-5..i-1])                   // 5-bar high break
(open - vwap[i]) / vwap[i] <= 0.02                    // still near value
stopDist from this bar's low, same helper as today
```

## Mechanism

Current surge waits for three green bars totaling ≥3% with a volume burst, so it fires on the last print of a short squeeze. That is why the signal is *more* wrong as the squeeze gets larger: +5m forward return is +11.7 bps on 3–4% bursts, +23.7 on 4–6%, and **−48.0 on 6%+** (7,926 of 14,168 hits); RSI 85+ is **−86.6**; volume 8×+ is **−41.5**; premarket is **−75.3**. Entering two bars earlier on those same hits — not a tradable rule, a diagnosis — returns +661 bps, which is the burst itself.

The first expansion bar is the start of that same volume event: a 5-bar high break on a volume surge while the open is still within 2% of VWAP and the prior bar was not already a surge. It selects a fatter right tail than a random minute on the same names (p95 +553 vs +308 bps at 5m; at 60m the median itself is +77 vs +45), which is the shape a rider with no profit target is built to hold.

## Falsifier

**Written before Builder implements this.** The idea dies if any of these hold after `surge.signalAt` is the function above:

1. `node research/edge.js` shows surge **+5m sig ≤ +5m rnd**. Reproduction is the test; the scratch measurement is not.
2. **+60m sig ≤ +60m rnd.** A 5-minute pop that does not persist is not a rider entry.
3. Signal count **> 2% of window bars**. Then it is a flood, and which fires become trades is the slot machine again.
4. The right tail that produces the mean collapses to a handful of prints: if the top 5% of +5m winners span **fewer than 100 unique symbol-days**, the mean is data, not a mechanism.

Falsifiers #1–#3 are for the implemented pod. #4 was run on the scratch signal before filing (below) and did not kill it.

## Cost

No change to `lib/data.js` discovery — same ranked movers, same universe. Signal count 14,168 → 34,127 (2.4× more minutes on those names). Live fills are still slot-capped (`maxPositions`, one-pod-per-symbol). The first fire of each symbol-day is 12,128, almost the same count as current surge and as redgreen.

## Note to the red team

Do not grade this gently because it is the first replacement that beats random. Three things I could not rule out, and one I already ran:

- **The mean is a right tail.** +5m median is +3.5 bps against a mean of +46.0. Win rate is 51.0% vs 49.5% random. Dropping the top 1% of +5m signal returns leaves +15.7 vs rnd +13.7 (survives). Dropping the top 5% leaves **−18.3 vs +13.7 (dies)**. For a rider that is the thesis — hold the tail, do not cap it — but it is also the way a handful of halt-prints can fake an entry edge. Falsifier #4 is that test.

- **Falsifier #4, run 2026-08-28, did not kill it.** Top 5% of +5m winners: n=1,706 fires, **1,547 unique symbol-days, 822 unique symbols, all 144 days**. Bottom 5% is similarly spread (1,457 symbol-days). This is not five names. The left tail is real too (p10 −219 vs random −160), so a HWM-trail rider will still stop out of the duds; edge.js does not speak to that.

- **Premarket loses at the rider's horizon; after-hours loses at every horizon.** I did not restrict the window after seeing that — the candidate was scored on surge's existing 04:00–19:30 window. If you cut those slices out, you are testing a different signal. If you leave them in, a rider that holds 60 minutes will be dragging PM and AH entries that underperform a random minute on those same names.

- **Quantiles vs random, for the convexity claim:**

```

+5m sig  46.0  51.0%  -219    -69     3.5    107    326    553    1448
```

At +60m the median itself beats random. That is the number a rider actually needs, and it is a different measurement than the +5m mean.

One-print monsters exist (PLYX 2026-02-17 06:29 ET, +358% in 5m, +17% at 60m). Ten of those do not make the mean; they also do not prove the tape is clean.
