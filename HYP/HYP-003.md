# HYP-003 — surge buys the last print of a 3-bar squeeze; the first expansion bar buys the same event at the start

**Status:** building
**Date:** 2026-08-28  **Pod:** surge
**Instrument:** wall-clock horizons `e4ae3f1`; after-signal neighbourhood `ae685af`. Blended `bucket15` without the pre/post split is superseded as a verdict.

## Claim

Replacing surge's entry (`igniterSignal`: three consecutive green bars totaling ≥3% with volume ≥3.5× avg10) with the **first expansion bar** — a single green bar that (1) prints volume ≥ `volSurgeMult` × avg10, (2) closes above the prior 5-bar high, (3) opens within 2% of VWAP, (4) is not preceded by another green volume-surge bar, (5) has RSI14 < 80 — takes +5m forward return from **−27.6 bps to +40.9 bps** (n=34,127 fires, 0.464% of 7,349,065 window bars). Against the `ae685af` after-signal control: **+40.9 vs +24.9 (1.64×)** at +5m and **+148.1 vs +123.0 (1.20×)** at +60m. Same harness, other columns: window +12.1 (3.40×), hour +38.6 (1.06×), blended bucket15 +81.5 (0.50×; `..before` +157.0).

## Category

(b) entry signal in `lib/strategies.js` — **surge only**. New `signalAt`. Do **not** edit `igniterSignal`; igniter still uses it. Do **not** give the rider a target (invariant #4). `burstPct` becomes unused by this pod; leave `RANGES` alone.

Exact conditions at bar `i` (all causal, `avg10` already excludes the current bar):

```
inWindow, i >= 10, atr[i] present
close > open                                          // green
v >= volSurgeMult * avg10[i]                          // 3.5× default
close > vwap[i]
rsi[i] == null || rsi[i] < 80                         // pinned; do not use P.rsiMax (default 90)
NOT (prev bar green AND prev v >= volSurgeMult * avg10[i-1])   // first bar of the expansion
close > max(high of bars[i-5..i-1])                   // 5-bar high break
(open - vwap[i]) / vwap[i] <= 0.02                    // still near value
stopDist from this bar's low, same helper as today
```

## Mechanism

Current surge waits for three green bars totaling ≥3% with a volume burst, so it fires on the last print of a short squeeze. That is why the signal is *more* wrong as the squeeze gets larger: +5m forward return is +11.8 bps on 3–4% bursts, +18.2 on 4–6%, and **−61.7 on 6%+** (7,868 of 14,093 kept hits); RSI 85+ is **−75.7**; volume 8×+ is **−52.7**; premarket is **−76.2**. Entering two bars earlier on those same hits — not a tradable rule, a diagnosis — returns +639 bps, which is the burst itself.

The first expansion bar is the start of that same volume event: a 5-bar high break on a volume surge while the open is still within 2% of VWAP and the prior bar was not already a surge. It selects a fatter right tail than a random minute on the same names (p95 +533 vs +277 bps at 5m; at 60m the median itself is +45.5 vs +24.8), which is the shape a rider with no profit target is built to hold.

## Falsifier

**Written before Builder implements this.** The idea dies if any of these hold after `surge.signalAt` is the function above:

1. `node research/edge.js` shows surge **+5m sig ≤ +5m rnd**. Written against the window control (the only control when this was filed). After `e9ad2d8` the same file also prints hour and bucket15; those columns are in the result block. Reproduction is the test; the scratch measurement is not.
2. **+60m sig ≤ +60m rnd.** A 5-minute pop that does not persist is not a rider entry.
3. Signal count **> 2% of window bars**. Then it is a flood, and which fires become trades is the slot machine again.
4. The right tail that produces the mean collapses to a handful of prints: if the top 5% of +5m winners span **fewer than 100 unique symbol-days**, the mean is data, not a mechanism.

Falsifiers #1–#3 are for the implemented pod. #4 was run on the scratch signal before filing (below) and did not kill it. Re-run on the wall-clock instrument 2026-08-28 also did not kill it.

## Note to the red team

Do not grade this gently because it is the first replacement that beats random. Three things I could not rule out, and one I already ran. Bar-count numbers in the first filing are dead. The 0.49× vs blended bucket15 was the contaminated neighbourhood Fizz retracted; `ae685af` is the column that counts now.

- **Against the after-signal neighbourhood, first-exp is +40.9 vs +24.9 (1.64×) at +5m and +148.1 vs +123.0 (1.20×) at +60m.** vs hour is still a near-tie (1.06×). The blended bucket15 row remains 0.50× because `..before` is +157.0. Current surge on the same harness is −27.6 vs after −7.2 — still buying the wrong minute. Falsifier #1 as written was the window column; window is 3.40× and does not fire.

- **The mean is a right tail.** +5m median is +1.3 bps against a mean of +40.9. Dropping the top 5% of +5m signal returns leaves **−19.6**, which is below the after-control (+24.9) as well as the old window control (+9.4). Builder's backtest is that truncation happening: stops still 73.5% of exits, and the entire PF gain is the 125 flatten trades. Falsifier #4 (unique symbol-days) did not kill the tail's breadth; it does not speak to whether those exits fill. HYP-005 is the fill question on those same flatten prints.

- **Falsifier #4, re-run 2026-08-28 on wall-clock, did not kill it.** Top 5% of +5m winners: n=1,667 fires, **1,515 unique symbol-days, 807 unique symbols, all 144 days**. Bottom 5% is similarly spread (1,419 symbol-days). This is not five names. The left tail is real too (p10 −211 vs random −148), so a HWM-trail rider will still stop out of the duds; edge.js does not speak to that.

- **Drop-sample rates are not identical.** first-exp drop sig 2.3% / rnd 3.9%. Same direction as the original defect (signals sit in denser tape), now with equal horizons. If the drop rule is itself a selection effect, this is where to look.

- **Premarket loses at the rider's horizon; after-hours loses at every horizon.** I did not restrict the window after seeing that — the candidate was scored on surge's existing 04:00–19:30 window. If you cut those slices out, you are testing a different signal. If you leave them in, a rider that holds 60 minutes will be dragging PM and AH entries that underperform a random minute on those same names.
